# Write the PRD

## Overview

- **Step:** planning, as Maya (`agent: maya` in every MCP call).
- **Produces:** `.agentplugged/docs/prd.md` from `assets/prd-template.md`: a couple of pages for a
  personal tool, 1 200 lines at most (beyond, a PRD per domain linked by identifiers).
- **Reads:** `.agentplugged/docs/brief.md` once; of the research notes, `ux.md` and an existing
  PRD, only the sections you use or change.
- **Validation point:** a `document` point, or the end of planning (step 7).

## Before you start

- Maya not active in `state.get`: say so, go straight to the last step (Report) with `partial`.
- **Modes:** **create**; **update** (edit in place, never renumber); **review**
  (`references/prd-checklist.md`, `npx agentplugged docs check`, each finding with its line, then
  go straight to the last step (Report) with `partial`: never copy the template, never rewrite
  the PRD, never open the end of the phase).
- One question at a time.

## Identifiers

- `PU-n` journey, `EF-n` functional, `ENF-n` non-functional (threshold and measure), `MS-n` metric
  (target; one counter-metric at least). `AD-n` is Alex's: mention only.
- Defined where it opens a line, list item, heading or first table cell; elsewhere a mention.
- New: the highest ever used, retired ones included, plus one. Never renumbered nor reused;
  dropped: `EF-2 : (retirée) …` in French, `EF-2 : (retired) …` otherwise.

## Decisions

- **Open:** a need read two ways: `checkpoint.open`, `type: decision`, two to four options, your
  `recommendation`, no story. Never choose in the creator's place.
- **Mark:** `[open: G-…]` at the end of the sentence concerned, never before an identifier.
- **Apply:** once resolved, read its `resolution` and apply it as "Applying a resolution" says (reference `skill-rules`); drop the mark, add a row to "Decisions".

## Steps

1. **Start.** `agent.status` (`working`); `state.get`, `phase.current`: `framing` → `partial`;
   `planning` → go on; later → only on the creator's explicit ask, as a conflict naming what cites
   the changed identifiers.
2. **Draft.** Copy the template; remove the "Generated by agentplugged" line (`docs check` refuses
   it), the guidance comments, every `<…>` placeholder and unused sample ids. Each `EF-n` is one
   testable capability serving a `PU-n`, never a solution. Guesses: `[assumption]`.
3. **Review gate.** `references/prd-checklist.md`, then `npx agentplugged docs check` until clean.
   Then reconcile the inputs: a sub-agent runs `critique-deliverable/references/reconcile.md` on
   the brief and the creator's notes, `review.critique` under your id
   (`lenses: ["reconcile"]`, 5 findings at most); ask once, one gesture per finding.
4. **Show it** with its assumptions and open points; revise. Do not ask them to approve it here.
5. **Decision gate.** Every `decision` checkpoint of the phase, by any agent (yours and Stella's),
   resolved and applied; else open nothing, name them, `partial`.
6. **Commit.** `git branch --show-current` names a branch (else ask, open nothing); `git commit`
   the PRD, signed with the creator's name and email.
7. **Commit the PRD and validate it.** `blob_sha`: `git rev-parse HEAD:.agentplugged/docs/prd.md`.
   - **A UX specification is still to come** (Stella active, `ux.md` not committed): the PRD does not close the planning. Open a `document` checkpoint (the PRD's `path`, `branch`, `blob_sha`). Never open a second `document` point on the same `blob_sha`. Open it first, then ask the creator whether
     it suits them, once; `chat.answer` with their words: it approves the PRD, even though the planning goes on, and it will not ask again about this PRD.
   - **Nothing else is left in the planning**: `type: phase_end`, `phase: planning`, with the PRD
     and, only when `.agentplugged/docs/ux.md` exists, the UX specification: never open a `document` point as well. An approved, unchanged document is only cited.
   - **The planning is closed**: a `document` point.
   Whatever `npx agentplugged next --json` says, never leave the PRD without its point.
   `phase_review`: give its id. `DOCUMENT_REVIEW_OPEN`: that point first. `changes_requested`
   (`agent` `maya`): read the note, step 2, then a new point with `supersedes` set to the refused one's id.
8. **Report.** `story.result` (`complete` or `partial`), assumptions, questions, conflicts;
   `agent.status` `idle`.

## Rules

- Follow "Rules for skills and agents" (reference `skill-rules`): checkpoint before the question, ask once; a point the creator did not keep goes to `checkpoint.decide`; in French say « tu »; start with `memory.read`.
- Draw the requirements from the creator: never write one nobody asked for.
- Header: `id`, `kind`, `owner`, `links` only. Write only `prd.md`. Never decide the stack or the
  screens, never call another agent: hand back to Noah.
