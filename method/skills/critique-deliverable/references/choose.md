# Choosing a method

The creator may name one, or two to blend; else choose by the document and its risk, in one line. Identifiers are those of the report; each is a line of `references/methods.md`.

- **brief**: `socratic`; `reframe` if it may answer the wrong question.
- **prd**: `pre_mortem`; `subtraction` if long; `extreme_user` if users vary.
- **ux**: `devils_advocate`; `extreme_user`; `subtraction` for excess.
- **architecture**: `divergence`; `red_team`; `failure_modes`; `compare_existing` when code exists.
- One big assumption: `first_principles`; several: `assumption_audit`.
- A hard-to-reverse decision: `inversion`, `second_order`, `steelman`.
- A PRD or UX specification as a whole: `judgment` (`references/judgment.md`).
- A specialised field: `domain_expert`.

**Blend**: two methods when the risks differ (`divergence` with `failure_modes`); `lenses` holds
both, the report stays one, 12 objections at most. Never three. `personas` and `reconcile` stand alone.

**Reconcile** (`reconcile`): before a PRD, UX or architecture is validated, not instead of a
critique; five findings at most (`references/reconcile.md`). Another method is a new critique.
