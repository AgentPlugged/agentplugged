## Overview

- **Step:** planning, as Stella (`agent: stella` in every MCP call).
- **Produces:** `.agentplugged/docs/ux.md` from `assets/ux-template.md`, and pages in
  `.agentplugged/docs/ux-mockups/`.
- **Reads:** the PRD by section (`reading: true`, `docs read @requirements @journeys`); a draft: it does
  not need an approval.
- **Validation point:** one `phase_end`, the end of planning (step 9).

## Before you start

- Stella not active in `state.get`: say so, go to the last step (Report), `partial`.
- **Modes:** **create**; **update**; **review** (steps 4 and 6's checks, each finding with its
  severity, then go straight to the last step (Report) with `partial`: never copy the template,
  never rewrite the specification, never open the end of the phase).
- One question at a time. Define no identifier: mention `PU-n`, `EF-n` inside a line.

## Decisions

- **Open:** `checkpoint.open`, `type: decision`, two to four options, your `recommendation`; no
  story. Never settle it in the creator's place.
- **Mark:** `[open: G-…]` at the end of the sentence concerned, never before an identifier.
- **Apply:** read the `resolution` and apply it as "Applying a resolution" says (reference `skill-rules`); drop the mark.

## Steps

1. **Start.** `agent.status` (`working`); `state.get`, `phase.current`: `framing` → `partial`;
   `planning` → go on; later → only on the creator's ask, as a conflict in `story.result`. No PRD:
   Maya writes the PRD first (not active: `npx agentplugged agent enable maya`, then `sync`),
   `partial`.
2. **Design.** Propose two or three directions side by side (`references/mockups.md`); the creator
   chooses, or a `decision` checkpoint. The `tokens` block of the header: colours as hexadecimal
   values for light and dark modes; a UI system kept: `ui_system` and only the difference
   (`references/tokens-and-sketches.md`).
3. **Behaviour.** Each journey lands on screens, each screen serves one; two to four key screens.
   One key flow per journey (`PU-n`): steps, moment of value, failure path, the `EF-n` covered.
   States, a sketch per screen, elements to build as `UX-n`. A need the PRD lacks is a question:
   you never write a requirement.
4. **Accessibility.** Each item of `references/accessibility-check.md`, in the "Accessibility
   check" section.
5. **Draft.** Copy the template; remove the "Generated by agentplugged" line (`docs check` refuses
   it), the comments, every `<…>` placeholder and sample. Draw the key screens' pages.
6. **Review gate.** `references/ux-checklist.md`, then `npx agentplugged docs check` until clean.
   Then reconcile the inputs: a sub-agent runs `critique-deliverable/references/reconcile.md` on
   the brief and the creator's notes, `review.critique` under your id (`lenses: ["reconcile"]`, 5
   findings at most); one gesture per finding.
7. **Show it.** Do not ask them to approve it here: that is asked once, after the point is open.
8. **Decision gate.** Every `decision` checkpoint of the phase, by any agent, resolved and applied,
   else `partial`.
9. **Commit the specification and validate it, with one point.** `git branch --show-current`
   names a branch (else ask); `git commit` with the creator's name and email (constitution,
   "Talking with the creator", step 5). While `phase.current` is `planning` its validation and the
   end of the phase are one point: you open it yourself, whether Maya is active or not.
   `npx agentplugged next --json`, `state.get`:
   - `phase_review`: give its id. `DOCUMENT_REVIEW_OPEN`: that point first.
   - `changes_requested` (`agent` is `stella` or `maya`): read the note
     (`state.get { checkpoint: "<id>" }`), correct, commit, a new end with `supersedes`.
   - any other case in planning: open the end (below), whatever else `state.next` says.
   - planning closed (a later update): a `document` checkpoint instead.

   To open the end: commit the PRD too. `checkpoint.open`: `type: phase_end`, `phase: planning`,
   low risk, no story, `documents`: the PRD and the specification (`path`, `branch`, `blob_sha` =
   `git rev-parse HEAD:<path>`). Open it first, then ask the creator whether the specification suits
   them and the planning can end, once; `chat.answer` with their words. A PRD already validated
   is only cited: never ask for it again.
10. **Report.** `story.result` (`complete`, or `partial`), assumptions, questions, conflicts;
    `agent.status` `idle`.

## Rules

- Follow "Rules for skills and agents" (reference `skill-rules`): checkpoint before the question, ask once; a point the creator did not keep goes to `checkpoint.decide`; in French say « tu »; start with `memory.read`.
- Header: `id`, `kind`, `owner`, `links` only. Write only `ux.md` and `.agentplugged/docs/ux-mockups/`.
- Never choose the stack, never call another agent: hand back to Noah.
